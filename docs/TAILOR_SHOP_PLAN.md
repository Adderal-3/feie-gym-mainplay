# 《江湖布坊》改编方案 · 待评审

这份文件把“原版完成后，考虑改成服装坊”的想法整理成可讨论的首章方案。当前只做策划，不修改游戏、配置、素材或存档；实施排在原版主流程验收之后。

当前原版入口与真实验收范围见 [运行记录](LOCAL_RUNTIME.md)、[项目说明](../README.md) 和 [技术边界](../NOTES.md)。恢复的客户端与配置不等于完整原服务器：本地初值包含明确推断，商店货架是固定目录重构，原随机选品和自动刷新算法未恢复。改编评审只能复用已验证的行为基准，商店库存、选品和刷新需作为独立设计确认，不将未知服务端规则视作全量还原。

## 体验目标与参考范围

暂名《江湖布坊》。玩家代掌一间临河衣坊，在接单、制衣与修坊之间，追查失踪师父留下的衣谱。

氛围参考《逆水寒》手游带来的宋韵江湖联想：雨巷、木构街市、灯影水色、衣料质感，以及市井生活与门派往来的交织。人物、地名、门派、剧情、服装剪影和纹样另行原创，不采用参考作品的设定、角色、标识或具体美术图案。

视觉建议采用清润宋韵2.5D手绘，以月白、雾青、木褐为底，灯火与金线局部提亮。临河木构配竹帘、晒布架、半透窗纱；用麻的毛边、绢的细光、纱的透叠和锦的织纹区分材料。棋盘物品先保清楚剪影，细纹留给放大预览，雨滴、蒸汽、布角轻动作为氛围。这是本项目原创设计建议，尚未实施。

参考资料仅用于研究表达方法，不复制原服装、纹样或场景资产：

- 官方[裁花信／拂新柳预告（2026-03-31）](https://www.swordofjustice.com/zh-cht/news/official/20260331/40324_1293938.html)：研究春日衣装如何与环境色彩、材质和动作形成联系。
- 官方[版本更新公告V2.3.3（2026-09-24）](https://www.swordofjustice.com/zh-cht/news/update/20260924/40325_1315026.html)：研究枫林小驻的茶市、戏文与日常活动氛围，以及绣锦神针所提示的衣装工艺联想；上述布坊视觉方案是据此延伸的设计选择，不是官方项目设定。

希望玩家记住三件事：

- 一块布能看见用途与来处，合成升级能感到工艺在推进。
- 客人通过衣装讲自己的处境；订单改变店铺的人情关系。
- 衣坊修好一点，师父留下的线索就多一层；经营与悬念共同前进。

主循环保留“点击产出 → 拖动合成 → 完成订单 → 获得修缮资源 → 开放区域与工具”。正式主棋盘沿用已验证的9行×7列骨架，开场使用独立的短棋盘。首轮改编先验证题材与流程，再讨论经济数值和系统扩展。

## 原创起因与首章悬念

师父沈见微离坊七日，只留下一本缺页的《候衣录》和一句“先还衣，再寻人”。玩家暂时代掌布坊，尚未决定是否留下。

雨夜，河埠水位骤涨，衣坊后棚的排水槽被旧布絮堵住，棚架倾斜。被雨压住的三包衣料分别属于渡船人、临近药铺和一位尚未露面的远客。开场的目标是分清衣料、隔湿封护，并把已经接下的委托按约交还。

救下的旧账衣匣里夹着师父衣谱的半页。纸页没有藏宝方位，记的是一件衣服如何在内衬中藏下多次改针；封袋上的针路，又与师父离开前留下的一件旧行衣相同。玩家由此发现：师父这次远行，与某位穿过这件衣服的人有关。

首章以“还清第一笔衣债、修复前柜、辨出衣谱记号”为闭环，只揭示一个明确线索：约定的收衣地点是渡口。师父为何失踪、远客是谁，留到后续章节。

这条故事的推进来自保管责任、手艺判断和委托人的不同立场。雨夜抢救之后，衣料的归属、损伤与修补方式继续影响订单和对白。

## 主要人物与衣装方向

| 人物 / 组织 | 首章作用 | 视觉与语言方向 |
| --- | --- | --- |
| 玩家店主 | 临时代掌衣坊，逐渐作出留下的决定 | 便于劳动的短衫、束袖、围腰；对白利落，逐渐表现判断力 |
| 沈见微 | 失踪师父，通过衣谱批注与旧物出现 | 用严谨又带生活气的手艺批注建立性格，首章不直接解释去向 |
| 阿蘅 | 相邻药铺的送药人，帮助辨认包裹与旧账 | 衣袖有便于取放药包的暗袋，常从用途评价衣服 |
| 卫舟 | 渡船人，第一位正式客人 | 常年雨水磨损的行衣，关注耐磨、活动余量和衣摆长度 |
| 听澜社 | 往来河道的原创民间组织，后续引出成套衣装 | 水纹以断续针路表达，配色和纹样从自有设计发展 |
| 停云门 | 后续门派客户，偏礼仪、剑袖与远行装 | 门派装先从行动习惯、场合与工艺限制推导，再确定外观 |

首章先让普通人的穿衣需求成立。门派衣装在熟悉衣坊之后出现，成为更复杂的订单与纹样研究目标。

## 系统映射

以下是设计语义，不是本次要写入游戏的配置。

| 已验证的玩法结构 | 布坊主题表达 | 设计要求 |
| --- | --- | --- |
| 普通物品逐级合成 | 整理材料、加工半成品、完成工艺阶段 | 同系列保持轮廓与材质联系；升级后用途清楚 |
| 点击产出器 | 制具台、纺车、染缸、绣架 | 每个产出器对应清晰工序，保留储量、冷却与点击反馈 |
| 多产物与概率 | 工具、线料、辅料的不同出料 | 将概率用于材料供给，剧情关键物件由明确任务获得 |
| 箱子与蛛网等格子状态 | 未拆的衣料包、待整理的压货格 | 两层状态各有图形和清理反馈，保持原有解锁判定可读 |
| 订单与交付 | 修衣、赶制、补绣与成套衣装委托 | 每单至少说明穿衣人、使用场合、需求缘由 |
| 体力 | 劳作精力 | 沿用当前消耗和恢复规则作为首轮基准 |
| 金币类资源 | 工钱 | 用于经营支出，保持结算和消耗来源可追踪 |
| 星星类装修资源 | 修缮券 | 衣坊完成委托后获得，推动前柜、屋面、染房等修复 |
| 玩家等级 | 坊誉 | 解锁更复杂的工艺、客人与委托类型 |
| 装修区域与部件 | 前柜、陈衣架、染房、绣间、临河廊 | 每次修复带来可见变化，并解释新功能为何可用 |
| 背包、仓库与道具详情 | 布柜、料仓与工艺簿 | 保留管理能力，名称和图标服从布坊语境 |
| 图鉴 / 收集 | 衣谱、纹样集、门派衣装册 | 先整理已做出的材料和衣装，后续再评审独立收集玩法 |

初章物品先覆盖救料用品、裁剪工具、针线、素布与简单成衣。染色、刺绣和复杂门派套装依章节逐步加入。实际物品 ID、合成边、产出权重和订单需求应通过一张完整映射表维护，避免仅替换显示名称后留下语义断层。

开场的三次交付分别服务于“衬垫吸湿、分卷包护、封匣转移”。场景反馈展示不同衣料被转移到安全位置，后续对白承接救下的包裹与损伤记录。

## 首章十个节点

对白均为原创方向稿；正式字数、分页和演出节奏需要在手机竖屏中复核。

| 节点 | 玩家目标与玩法 | 故事进展 / 对白片段 |
| --- | --- | --- |
| 1 · 檐雨入坊 | 短演出交代三包寄存衣料受雨，明确第一项操作 | 阿蘅：“先别搬最上头那包，下面是药铺的细绢，压湿了会粘在一处。” 玩家：“把空案腾出来，我来分。” |
| 2 · 垫布分湿 | 用首两次拖动合成完成衬垫，救出第一包料 | 玩家：“外层湿，里头还干。先垫开，别急着烘。” 阿蘅：“你这几下，倒像沈师父亲手教的。” |
| 3 · 护卷转移 | 点击产出器取得包护材料，完成第二项交付 | 玩家：“这匹布的经线松了，得顺着卷，不能拧。” 衣料转移后露出写有收衣日期的旧签。 |
| 4 · 封匣留证 | 完成第三项救料交付；记录包裹归属和受损处 | 阿蘅：“这只旧匣子也算客货？” 玩家：“封口有师父的针。我先照原样收着。” |
| 5 · 半页衣谱 | 离开短棋盘，查看衣谱；确立首章目标 | 师父批注：“衣有旧痕，先认其故，再落新针。” 玩家：“师父留的是修衣法，还是叫我认什么？” |
| 6 · 开门接衣 | 进入正式棋盘，整理工具、合成针线，完成渡船人的第一单 | 卫舟：“衣摆再短半寸，收缆时就不会踩住。” 玩家：“留够上船的步子，风里也不露腿。我记下了。” |
| 7 · 修好前柜 | 使用订单所得修缮券修柜；完成第一轮经营反馈 | 阿蘅：“柜子补好了，客人总算有地方放衣。” 玩家：“也得有地方把账摊明白。谁的料、欠什么，都写在这里。” |
| 8 · 新具试针 | 领取原有结构中的工具奖励，合成升级工具，阅读首次升级说明 | 玩家：“旧盒里还有一把能用的裁剪。刃口磨过，正好裁厚料。” 提示说明新产物与产能变化，再进入下一次点击操作。 |
| 9 · 暗线成章 | 完成补绣委托，在裁片与衣谱间辨认同一种针路 | 阿蘅：“补口为什么多走一折？” 玩家：“这不是多出来的。拆开旧针，才看得见后一个记号。” 衣谱解出“渡口收衣”的约定。 |
| 10 · 留灯候客 | 交还首章委托，修好门灯；玩家决定继续经营并赴约 | 玩家：“先把答应的衣做好。明日去渡口，问师父最后交的是哪一件。” 门灯亮起，出现一封尚未拆开的听澜社衣单。 |

节点 1–4 使用独立救料场景，节点 6 起落入常规经营循环。剧情关键提示须与当前可操作目标一致；道具升级、领取奖励、关窗和装修确认沿用已经验收的操作节奏。

第一单与补绣委托的具体物品数量待映射表完成后确定。首章不同时叠加门派声望、自由染色和战斗等新系统。

## 必须重做的内容

| 资产 / 内容 | 需要完成的工作 | 验收重点 |
| --- | --- | --- |
| 人物与演出 | 玩家、阿蘅、卫舟、师父相关旧物，原创立绘、表情与动画 | 人物剪影、语言和行为能分别成立；对白演出没有原角色残留 |
| 开场场景 | 雨棚、河埠、湿衣料、旧衣匣、移料反馈与雨水表现 | 三项救料目标可从画面辨认，每次交付都有对应变化 |
| 合成物品 | 全部上线物品的材料、工具、半成品、成衣与产出器图 | 合成链自洽；相邻等级可辨；首章关键物品在小尺寸下清楚 |
| 衣坊与装修 | 屋面、前柜、布柜、制具台、门灯及后续工坊部件 | 破损、修复、可操作三种状态完整；施工顺序符合空间用途 |
| 界面与反馈 | 顶栏、棋盘、格子遮罩、订单、详情、升级、奖励与引导外观 | 不靠颜色单独区分状态；点击区与视觉一致；文字在竖屏可读 |
| 剧情与配置文案 | 所有对话、任务、订单、物品说明、衣谱批注与系统提示 | 物品、客户、奖励和修坊目标相互对应，连续游玩没有语境跳转 |
| 声音与字体方案 | 雨声、木作、裁布、纺线、交付音效，配乐和字体选型 | 提示音能辨认；循环音乐与对白节奏协调；资源来源明确 |

纹样从原创的植物形态、行旅用途、工具痕迹和组织故事发展，先画成可解释的纹样稿，再应用到衣装。门派套装需要自己的结构和工艺逻辑。

现有提取素材继续用于原版基准验收。改编版上线范围内的图像、角色、剧情与声音按新的资产清单交付，不能因为旧资源已经能运行就省去主题制作。

## 可复用的技术与工程成果

- 已验证的棋盘状态、拖动坐标、合成判定、产出器储量与冷却、订单结算、装修解锁等规则，可以作为改编实现与回归测试的基准。
- 数据表驱动的方法可继续使用。将物品、系列、订单、装修和剧情映射集中到独立主题配置中，先建立完整对应关系，再接新内容。
- 本地 HTTP 启动、资源路由、原始纹理解码、依赖闭包检查、SHA 清单与缺失资源诊断的工具可用于制作流程。
- 离线存档校验、操作日志、刷新恢复和断网验收方法可继续使用。改编版必须采用独立存档键与版本，不覆盖原版存档。
- 原生输入验收脚本与逐步截图方法可以复用；新的资产尺寸、锚点、遮罩、动画和文字仍须重新验证。

原编译客户端保留为固定的行为参考。正式改编工程优先形成可维护的模块与配置入口，逐步明确哪些逻辑可迁移、哪些需要重新实现，不在体量很大的编译文件里持续堆叠主题替换。

## 阶段与验收

| 阶段 | 交付物 | 通过条件 |
| --- | --- | --- |
| 0 · 原版收尾与方案评审 | 原版验收记录、本方案、首章流程图和内容边界 | 原版标准剧情与主循环有明确验收结果；确认首章目标、人物、救料起因与主题范围后，再开始改编 |
| 1 · 映射与视觉样张 | 首章物品 / 订单 / 装修 / 剧情映射表；人物、衣坊和棋盘样张 | 每条合成链、每个订单、每次装修都能解释用途；关键物品轮廓可辨；确认一套统一视觉方向 |
| 2 · 首章完整可玩段 | 独立入口与存档，十节点剧情，救料短棋盘、正式棋盘、首单、修柜与工具升级 | 无需原服务器完成“救料→接单→修坊→升级工具→取得渡口线索”；无缺图、无阻断、无旧故事文案；刷新后能继续 |
| 3 · 内容与手感验收 | 文案、动画、声音、全部初章资产与回归记录 | 用新存档连续完成首章；停在对话、合成、交单、装修和弹窗中途分别重载，状态正确；触摸、遮罩、合成反馈与文字排版通过真机尺寸检查 |
| 4 · 后续章节决策 | 首章反馈、后续衣装与工坊清单 | 根据实际游玩确认继续制作的章节、产出链和门派衣装；另行评审染色、纹样定制与经营扩展 |

阶段 2 应记录实际首章时长、操作次数、等待位置和玩家误解，而后再定节奏调整。关键剧情通过明确交付推进，避免为了等一个随机产物而卡住首章线索。

## 下一次评审需要作出的选择

1. 美术表现偏轻巧卡通，还是更重视宋韵材质的插画风；先用同一人物、同一棋盘和同一衣坊角落比较样张。
2. 师父失踪线索在首章占多大比重，以及玩家留下经营衣坊的动机是否充分。
3. 首章交付范围与预算：先完成上述闭环，再确定门派套装和自由染色的制作顺序。

本文件不代表这些选择已经确定，也不触发游戏改动。原版完成后，可据此进行一次具体的内容与制作评审。
