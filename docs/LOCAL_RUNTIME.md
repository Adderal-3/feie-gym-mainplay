# 本地启动、存档与验证范围

## 启动方式

保留完整仓库，安装 Node.js 22 或更新版本。Windows 双击根目录的 `启动本地版.cmd`，或运行：

```sh
node tools/launch-original.mjs
```

启动器会检查本地 4174 端口，必要时启动服务，然后打开 `http://127.0.0.1:4174/`。服务只监听 127.0.0.1。若仅需服务和日志：

```sh
node tools/original-server.mjs
```

不需要 npm ci 或 npm registry。运行服务只依赖 Node 内置模块；原引擎、脚本、配置、字体、纹理和音频由本地文件提供，不在遇到缺失时自动回源 CDN。关闭启动的服务后，再次运行启动命令即可继续使用。

本项目需要本地 HTTP 资源服务，不能通过双击 original/index.html 的 file:// 地址替代。无需安装、登录或连接原微信小游戏。

## 如何操作

游戏使用原界面和原引导。按画面中的手势拖动相同道具进行合成，点击已解锁的原产出器生成物品，按顶部原订单交付道具，再使用星星进行原装修流程。

普通物品与产出器的升级目标、产出权重、储量、冷却、体力消耗和订单奖励取自恢复的配置。本地入口不额外加入无限体力、免费补给或缩短冷却等试玩按钮。背包、道具信息和原窗口沿用原客户端控件；背包按原配置在 5 级解锁，本轮未进行背包的原生操作验收。

本地适配覆盖的指令清单可由 LocalBackend.getSupportedCommands() 查看。活动、支付、广告和社交等运营业务未实现；imgbox_show 外观拥有查询也仍未接入。未接入的指令返回明确错误，原界面中出现入口不代表该业务已可用。

## 存档

本地适配器在所接入的结算操作后保存进度，并在页面离开时尝试持久化。存档位于浏览器本地存储，正常入口使用键 `feie-gym-original-local-v2`，与开发期间的 QA 存档分开。

再次打开同一浏览器和同一地址时，会恢复原模型中的棋盘、订单、背包、资源与引导进度。恢复时校验版本、原物品 ID、63 个格子、Map、计时数据和非负资源；无效存档不会直接用于结算。

不同浏览器、不同端口以及 localhost 与 127.0.0.1 通常使用不同存储空间。清理网站数据、使用隐私窗口或禁用存储会影响持久化。项目没有云同步，也不会读取原微信账户的在线存档。

开发排障时可用浏览器控制台查看 window.__LOCAL_BACKEND__ 的 snapshot()、persist()、readSave()、getLog() 和 getUnlockErrors()。clearSave() 只删除本地存档；调用前应自行保留需要的进度备份。它们是排障 API，不是新增的原游戏按钮。

## 排障

- 空白画面或加载失败：查看启动终端及 `http://127.0.0.1:4174/?debug=1`。/__diagnostics 列出本地请求缺失项，不会回源补取。
- 报 Original client SHA or bridge layout mismatch：客户端脚本与已验证注入位置不一致。恢复仓库原文件；开发者有意修改原脚本后，需安装开发依赖并重新运行 `node tools/build-original-layout.mjs`。
- 端口被其他程序占用：先确认占用程序；不要把其他 HTTP 服务当作游戏服务。关闭自己启动的旧实例后重试，或通过 ORIGINAL_PORT 自行指定端口并直接打开该地址。启动器默认仍使用 4174。
- 某个弹窗提示尚未实现指令：这是本地结算范围之外的原业务，不会授予虚构资源。
