# 本地启动、存档与验证范围

## 启动方式

保留完整仓库，安装 Node.js 22 或更新版本。Windows 双击根目录 `启动本地版.cmd`，或运行：

```sh
node tools/launch-original.mjs
```

启动器在本地 4174 端口启动服务并打开 `http://127.0.0.1:4174/`。仅启动服务可用 `node tools/original-server.mjs`。服务只监听 127.0.0.1，运行只依赖 Node 内置模块，不需要 npm 安装、微信登录或原服务器。引擎、配置、字体、纹理和音频从本地读取，缺失资源不自动回源。

需要本地 HTTP 服务，不能双击 `original/index.html` 代替。不同端口、浏览器及 `localhost` 与 `127.0.0.1` 使用不同存储空间。

## 当前原版路线

当前采用独立 6.2.3 快照，createVersion 为 14。标准 Z7 / PlayableBoard_14 先播放 991/992 纵火与营救对白，再进入配置 Board9000 的4行×7列救火棋盘；三轮目标完成后，原 Main/c9/d9 进入 Board_14 的 Board100 主棋盘、抽屉996与 Build1_13。

按原提示拖动相同道具合成，点击产出器，交付订单，使用星星重建健身房。主棋盘为7列×9行。数据由原配置与 q6 的 AB 覆盖决定，本地入口没有另加无限体力、免费补给或缩短冷却按钮。

本地起点为金币0、钻石20、体力100。金币、钻石根据参考工具箱里程碑余额及原首次装修奖励推断，是明确选定的本地值，**不是恢复出的服务器新号数据**。AB14 的选择、模型 ID 与种子也不代表恢复了原开户或分流算法。依据见 [story-profile.js](../original/story-profile.js)。

商店使用原界面和配置，货架选品属于**本地固定目录重构**：从已解锁、固定单一虚拟货币价格的商品按ID选取，购买使用原商品、库存及价格规则，手动刷新使用原虚拟货币费用。原服务器随机选品、随机价格和自动刷新算法未恢复，不宣称该货架与线上一致。已原生验证手动浏览、一次购买、入盘与重载恢复；完整Shop引导与商店手动刷新交易不在通过范围，后端测试不能替代这些项目。

## 存档

正常入口使用键 `feie-gym-original-story623-v1`。`?debug=1&profile=名称` 使用同键加 `:名称` 后缀，隔离 QA 进度。旧 `feie-gym-original-local-v2` 及开发档保留，**不自动迁移到当前剧情**，避免旧分支引导和订单混入参考路线。

适配器在已接入操作后保存原模型，离开页面时也尝试保存。恢复检查版本、原物品 ID、主棋盘格子、Map、字节标记、计时数据及非负资源。原 el 计时模型在界面挂载阶段由 `G2.convertRecovery` 构建原运行恢复器。

原引导按关键步骤恢复，不保存每段临时动画。Build1_13 的9913205等待升级窗口步骤不是关键步；刷新后原客户端可从上一关键步进入9913206。`MQ.cachedRewards` 仅存在内存，已结算道具仍在存档渠道中；这不能证明升级奖励窗口已实际播放。

清理网站数据、隐私窗口或禁用存储会影响进度。项目没有云同步，不读取微信在线账户。排障 API `window.__LOCAL_BACKEND__` 提供 `snapshot()`、`persist()`、`readSave()`、`getLog()` 和 `getUnlockErrors()`；删除前应保留需要的存档。这些不是新增游戏按钮。

## 自动化与静态检查

```sh
npm run test:original
```

覆盖全部 `tests/original-*.test.mjs`：原请求、结算原子性、模型与恢复器持久化、剧情角色初始化、原 AB 解析和本地服务。AB14 回归直接执行恢复的 q6、UT、解锁与产出方法，检查1001/1002、首次装修及等级奖励，防止混入旧10001订单与91101礼包。数量和结果以当次命令输出为准。

安装开发依赖后运行 `npm run verify`，同时检查早期恢复与 reference623 包文件、client 来源切片、当前 BON 源与解码 JSON、可读脚本来源及 AST、注入位置。结果见 [verification.json](verification.json)；其中 `runtimeVerified=false` 表示报告只负责静态校验，真实游玩记录如下。

素材数量、入口与缺失项见 [资产报告](original-assets-acceptance.json)、[依赖图](original-mainplay-dependencies.json) 与 [下载清单](../recovered/downloads/manifest.json)。静态闭合仅覆盖报告列明的范围，动态奖励与装修素材仍需实际流程检查。

## 排障与重放

- 空白或加载失败：查看服务日志与 `http://127.0.0.1:4174/?debug=1`；`/__diagnostics` 列出本地缺失请求。
- `Original client SHA or bridge layout mismatch`：恢复正确文件；有意重建时显式运行 `node tools/build-original-layout.mjs recovered/reference623/client/subpackages/main/game.js`。
- 端口占用：确认占用程序后关闭自己的旧实例，或用 `ORIGINAL_PORT` 启动独立服务；默认启动器仍使用4174。
- 尚未实现指令：属于本地范围之外的原业务，明确失败，不返回通用成功响应。
- 重放首次升级：用独立 QA profile，在真实首两单完成、首次建造前保存完整 `snapshot()`；只恢复该 QA 完整检查点后从原入口重放，不修改引导步号、等级或资源。正常玩家存档保持独立。
